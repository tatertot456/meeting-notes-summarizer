Delivery Modes, Broadcast & Collision Domains

▶

Three fundamental delivery modes define how a sender addresses its recipients on an IP network.

Unicast (1-to-1)

One sender to one specific destination IP/MAC. Used for HTTP, SSH, and file transfers.

Multicast (1-to-Many)

One sender to a subscribed group. Used for IPTV, video streams, and OSPF routing updates.

Broadcast (1-to-All)

One sender to every device in the L2 domain. Used for ARP requests and IPv4 DHCP Discover.

Broadcast Domains:

  • L2 Domain Boundary: The collection of all devices that receive a L2 broadcast frame. Switches flood broadcasts to all active ports.
  • Router Separation: Routers and L3 interfaces strictly block L2 broadcasts from crossing into adjacent subnets.
  • VLAN Isolation: Separate VLANs create distinct logical broadcast domains on the same physical switch hardware.

Collision Domains:

  • Concept: A network segment where simultaneous transmissions can collide and corrupt signals.
  • Legacy Hubs: A hub creates ONE shared collision domain for all connected endpoints.
  • Switches & Full-Duplex: Every switch port is a separate collision domain. Full-duplex switched Ethernet eliminates collisions entirely.

Media Access & Payload Rules

▶
  • IP MTU vs Frame Size: Standard IP MTU = 1500B payload. Full Ethernet frame = 1518B (14B header + 4B FCS).
  • Jumbo Frames (9000B): Used in high-speed datacenters and SAN storage to reduce per-GB CPU overhead. TCP dynamically increases MSS during the handshake to fit the larger MTU.

CSMA/CD (Wired Half-Duplex)

Carrier Sense Multiple Access with Collision Detection. Listen before Tx; if a collision occurs, send a Jam signal and wait a random backoff time. Core of the original Ethernet protocol.

CSMA/CA (Wireless 802.11)

Collision Avoidance used in Wi-Fi. Wireless nodes cannot detect collisions while transmitting, so they wait a random backoff slot and require explicit ACKs.

Traffic Shaping, Prioritization & QoS Marking

▶

Traffic Shaping (Rate Control)

Smooths out sudden traffic bursts by queuing packets and releasing them at a predictable, constant bit rate. Example: capping backup jobs to 30 Mbps on a 100 Mbps WAN link.

Traffic Prioritization

Selects which queued packets transmit first during congestion. Example: forwarding real-time voice packets before web downloads.

Traffic Classification

Identifies traffic by source/dest IP, VLAN, TCP/UDP port, DSCP tag, or application identity to apply QoS policies.

QoS Marking at Multiple Layers:

LayerMechanismDetail
Layer 2PCP (802.1p)3-bit Priority Code Point inside the 802.1Q VLAN tag. Values 0–7; Voice = 6 (High), Backups = 1 (Low).
Layer 3DSCP (IP Header)6-bit Differentiated Services Code Point in the IP header. Routers map tags into high-priority queues for low-latency forwarding.
Layer 4Port ClassificationFilter by TCP/UDP service port. Example: UDP Port 5060 = SIP VoIP signaling.

Spanning Tree Protocol (STP)

▶

Because Ethernet frames lack a Layer 3 TTL field, physical loops cause endless broadcast storms, MAC table instability, and total network crashes. STP eliminates loops while keeping redundant links available as backups.

Classic STP (802.1D)

Runs a single, global spanning tree for the entire physical network — ignores VLAN boundaries.

PVST / PVST+ / Rapid PVST+ (Cisco)

Separate STP instance per VLAN. Enables different root bridges per VLAN, allowing L2 load balancing across redundant links. Default on Cisco switches.

MSTP (802.1s)

Maps multiple VLANs into groups sharing one STP instance. Reduces CPU and control traffic overhead in large environments with hundreds of VLANs.

STP Mechanics:

  • Root Bridge Election: Switches exchange BPDUs to elect the Root Bridge — the switch with the lowest Bridge ID / MAC address wins.
  • Loop-Free Topology: STP calculates the lowest-cost path to the Root Bridge. Redundant links are placed in a Logically Blocked state, remaining ready as backups.

Physically redundant links provide instant hardware failover. STP keeps them logically blocked to prevent loops — if the active link fails, the blocked port transitions to forwarding automatically.

  • 802.1Q Tagging: Inserts a 4-byte header into the Ethernet frame to identify VLAN membership across trunk links.
  • Native VLAN: VLAN whose traffic is sent untagged on a trunk — must match on both ends of the link for security.
  • SFP / SFP+: Modular transceiver slots for fiber or copper. SFP = 1 Gbps, SFP+ = 10 Gbps.

VTP (VLAN Trunking Protocol) is a Cisco proprietary L2 protocol that auto-synchronizes VLAN configurations across all switches in a shared domain. An admin configures VLANs on a VTP Server; all client switches sync automatically via trunk links. VTP uses revision numbers — a higher revision number overwrites lower ones on receiving switches, which can be dangerous if a misconfigured switch is introduced to the domain.

VLAN Design, Deployment & Configuration

▶
  • Group by Role or Function: Faculty, Students, Guest — or Data, Voice, Video, Management.
  • 1 VLAN = 1 Subnet: Align each VLAN to one IP subnet (e.g., 10.10.10.0/24) for clean L3 routing and ACL policy boundaries.
  • Deployment: Use 802.1Q trunks with explicit allowed VLAN lists (switchport trunk allowed vlan 10,20) to restrict unnecessary broadcast traffic.
  • Security: Disable DTP (switchport mode access) on user ports. Move native VLAN off VLAN 1 to a dedicated unused ID (e.g., VLAN 999). Shut down unused ports.

Router-on-a-Stick (ROAS) — Subinterface:

 ip address 10.10.10.1 255.255.255.0

Layer 3 Switch SVI:

interface vlan 10

Link Aggregation, PoE & Duplex

▶

EtherChannel / LAG combines up to 8 physical Ethernet links into ONE logical high-speed connection. Four 1-Gbps links = a 4-Gbps logical trunk. If one cable fails, traffic automatically redistributes across remaining links.

LACP (802.1AX) — Link Aggregation Control Protocol dynamically negotiates and maintains LAG group trunks between switches. No manual per-port configuration required.

PoE (802.3af) — 15.4W

Supplies power and data over a single Cat6 cable to IP phones, basic access points, and sensors.

PoE+ (802.3at) — 30W

Double the power for PTZ security cameras, Wi-Fi 6 APs, and video conferencing units.

  • Auto-MDI/MDI-X: Interfaces automatically detect transmit/receive wire pairs, eliminating the need for crossover cables (copper only, not fiber).
  • Duplex Autonegotiation: Configures full-duplex speed automatically. A mismatch causes severe late collisions and packet loss.

VLAN Hopping Attacks & Hardening

▶

Switch Spoofing

An attacker configures their device to negotiate a trunk link using DTP (Dynamic Trunking Protocol), gaining unauthorized access to all VLANs on the switch.

Double-Tagging Attack

Attacker sends a frame with TWO 802.1Q tags — [Native VLAN 1][Target VLAN 20]. The first switch strips tag 1; the inner tag 20 then reaches the target VLAN undetected.

Hardening Best Practices:

  • Explicit Access Mode: switchport mode access — disables DTP auto-trunking on all user-facing ports.
  • Shutdown Unused Ports: Issue shutdown on all unused ports and assign them to an isolated parking-lot VLAN.
  • Dedicated Native VLAN: Change the native VLAN from VLAN 1 to a dedicated unused VLAN (e.g., VLAN 999) on all trunks.
  • Restrict Trunk VLANs: Use switchport trunk allowed vlan to permit only required VLANs. Use switchport nonegotiate to disable DTP on trunk ports.

Port Security & Layer 2 Defense Suite

▶

Port Security (MAC Restrict)

Restricts allowed MAC addresses on an access port. Sticky MAC learning dynamically binds the first connected device's MAC and locks it in.

Violation Actions

Protect — drops unauthorized frames silently. Restrict — drops and logs the event. Shutdown — places port in error-disabled state.

DHCP Snooping

Blocks rogue DHCP servers by filtering untrusted ports. Only designated trusted ports can send DHCP offers to clients.

Dynamic ARP Inspection (DAI)

Validates incoming ARP messages against the DHCP snooping binding table to prevent ARP poisoning and man-in-the-middle attacks.

SPAN Port Mirroring & Switch Troubleshooting

▶

Port Mirroring (SPAN) copies ingress/egress frames from source switch ports or VLANs to a destination diagnostic port where a Wireshark analyzer captures traffic without interrupting live operations.

  • Diagnostic Uses: Latency troubleshooting, protocol handshake inspection, DNS/DHCP failure analysis, intrusion detection.
  • Security Note: SPAN ports expose unencrypted payload data — destination ports must be strictly secured.

Cisco SPAN Configuration:

Switch# configure terminal
Switch(config)# monitor session 1 source interface range GigabitEthernet0/1 - 3 both
Switch(config)# monitor session 1 destination interface GigabitEthernet0/24
Switch(config)# end
Switch# show monitor session 1

5-Step Switch Troubleshooting Workflow:

StepAction
1. Identify Port RoleVerify if interface is configured as Access, Trunk, Routed, or Management.
2. Check ConfigurationVerify assigned VLAN, allowed trunk list, speed/duplex, and operational status.
3. Inspect Port CountersCheck for interface errors, late collisions, buffer drops, or flow control events.
4. Mirror & CaptureEnable SPAN mirroring and inspect packet headers in Wireshark.
5. Audit Security ViolationsCheck MAC table bindings and verify port security error-disabled states.

Security Zones, DMZ & NAT/PAT

▶

Trust Zone Classifications: Untrusted (Internet) → DMZ (Web/Mail/DNS) → Trusted (Internal/EHR/DB) → Restricted (Domain Controllers).

DMZ (Demilitarized Zone)

Isolates public-facing servers. Firewall rules permit inbound HTTPS 443 to the DMZ but strictly block all DMZ-to-Internal connections.

Jump Servers (Bastion Hosts)

Hardened intermediate hosts with MFA and central logging used for secure administrative access into restricted zones.

NAT

Translates private RFC 1918 IPs (10.0.0.0/8, 192.168.0.0/16) to public routable IPs at the border router.

PAT / NAT Overload

Maps hundreds of internal private sockets (192.168.1.10:51500) to ONE public IP using unique source port numbers (203.0.113.10:40001).

Honeypots are isolated decoy systems deployed to detect, log, and analyze unauthorized scanning and attack techniques without exposing real infrastructure.

Access Control Lists (ACLs)

▶

An ACL on a router is a sequential list of permit or deny rules that filter network traffic based on IP addresses, protocols, and port numbers.

Standard ACLs

Filter based strictly on Source IP only. Place close to the destination to avoid blocking traffic prematurely.

Extended ACLs

Filter on Source/Dest IP, Protocol, and TCP/UDP Ports. Place close to the source to stop unwanted traffic early.

  • Top-to-Bottom Processing: Rules are evaluated sequentially. Once a match is found, processing stops immediately — rule order is critical.
  • Implicit Deny Any: All ACLs end with an invisible deny ip any any rule — all traffic not explicitly permitted is silently dropped.

A set of ACLs can provide rudimentary packet filtering, but they are no substitute for a stateful firewall. ACLs evaluate each packet independently with no awareness of connection state — a stateful firewall tracks whether a packet belongs to an established session.
