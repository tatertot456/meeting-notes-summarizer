Core Network Services Overview

▶

When a new device joins the network, a chain of core services fires automatically in sequence to bring it fully online. Each service depends on the previous one succeeding.

1. DHCP

Assigns IP address, subnet mask, default gateway, and DNS server address automatically via the DORA handshake.

2. DNS

Translates human-readable hostnames (google.com) into routable IP addresses so the device can reach resources by name.

3. NTP

Synchronizes the device clock to a trusted time source. Accurate time is required for Kerberos tickets, TLS certificates, and log correlation.

4. Directory Services

LDAP/Active Directory authenticates the user, applies GPOs, and grants RBAC-based access to network resources.

DNS Hierarchy & Name Resolution

▶

DNS is a globally distributed, hierarchical database that maps domain names to IP addresses. No single server holds all records -- resolution is delegated down the tree.

  • Root Zone (.): The top of the DNS tree. 13 sets of root server clusters worldwide (operated by ICANN and partners). Returns the authoritative nameserver for the requested TLD.
  • TLD Servers (.com, .org, .edu): Operated by registries. Return the authoritative nameserver for the specific domain (e.g., google.com).
  • Authoritative Nameserver: Holds the actual DNS zone file for the domain. Returns the final answer (IP address) for the queried hostname.
  • Recursive Resolver: Your ISP or corporate DNS server. Walks the hierarchy on your behalf, caches results for the TTL period, and returns the answer to the client.

Resolution walk for www.example.com: Client asks Recursive Resolver → Resolver asks Root (.) → Root refers to .com TLD → .com refers to example.com nameserver → example.com nameserver returns the A record IP → Resolver caches and returns to client.

DNS Zone Database Architecture

▶

Forward Lookup Zone

Maps hostnames to IP addresses. The standard zone type -- queried for every normal DNS resolution (A and AAAA records).

Reverse Lookup Zone

Maps IP addresses back to hostnames (PTR records). Used by security tools, mail servers, and logging systems to identify devices by IP.

Primary Zone

The authoritative read/write copy of the zone. All record changes are made here and replicated to secondary zones.

Secondary Zone

Read-only replica of the primary zone. Provides redundancy and load distribution for DNS queries. Updated via zone transfer (AXFR/IXFR).

  • Zone Transfer (AXFR): Full transfer of all zone records from primary to secondary. Should be restricted to authorized secondary servers only -- unrestricted AXFR exposes your entire internal DNS to attackers.
  • TTL (Time to Live): How long resolvers cache a DNS record before re-querying. Short TTL = faster propagation of changes; long TTL = less DNS traffic but slower updates.

DNS Zone File Example

▶

A zone file is the flat-text database that an authoritative nameserver reads. Each line is one resource record.

$ORIGIN example.com.
$TTL 3600

; SOA — zone authority record
@   IN  SOA  ns1.example.com. admin.example.com. (
                2024110101  ; Serial (YYYYMMDDnn)
                3600        ; Refresh
                900         ; Retry
                604800      ; Expire
                300 )       ; Minimum TTL

; Nameservers
@       IN  NS    ns1.example.com.
@       IN  NS    ns2.example.com.

; A records
@       IN  A     93.184.216.34
www     IN  A     93.184.216.34
mail    IN  A     93.184.216.50
ns1     IN  A     93.184.216.10
ns2     IN  A     93.184.216.11

; Mail exchanger
@       IN  MX  10  mail.example.com.

; Alias
ftp     IN  CNAME  www.example.com.

; SPF record
@       IN  TXT   "v=spf1 mx ~all"

DNS Encryption

▶

Traditional DNS sends queries in plaintext over UDP port 53 -- anyone on the network can read exactly what hostnames you are resolving. Three standards address this.

DoT — DNS over TLS (Port 853)

Wraps DNS queries inside a TLS tunnel. The DNS payload is encrypted but the destination IP (port 853) reveals that DNS is happening -- firewalls can inspect and filter it.

DoH — DNS over HTTPS (Port 443)

Sends DNS queries inside standard HTTPS traffic. Completely hides DNS from network inspection tools -- indistinguishable from normal web browsing. Preferred by browsers (Firefox, Chrome).

DNSSEC — DNS Security Extensions

Cryptographically signs DNS records so resolvers can verify responses have not been tampered with. Prevents DNS cache poisoning attacks. Does NOT encrypt queries -- it only provides integrity, not confidentiality.

DNS Cache Poisoning: An attacker injects a forged DNS response into a resolver's cache, redirecting users from a legitimate site to a malicious one. DNSSEC defeats this by requiring valid cryptographic signatures on all records.

DHCP DORA — Automated IPv4 Address Allocation

▶

DHCP eliminates manual IP configuration. When a device connects to the network, it completes a 4-step broadcast handshake to obtain addressing information.

StepMessageDirectionWhat Happens
1DiscoverClient → BroadcastClient broadcasts "I need an IP address" to 255.255.255.255. No IP yet -- source is 0.0.0.0.
2OfferServer → BroadcastDHCP server responds with an offered IP, subnet mask, gateway, DNS server, and lease duration.
3RequestClient → BroadcastClient broadcasts acceptance of the offered IP (still broadcast -- other DHCP servers retract their offers).
4AcknowledgeServer → ClientServer confirms the lease. Client configures its interface and is fully online.

Lease Renewal: At 50% of lease time the client sends a unicast Request to renew with the same server. At 87.5% it broadcasts to any available server. If no renewal occurs before expiry, the IP returns to the pool.

DHCP Scopes, Pools, Exclusions & Reservations

▶
  • Scope: The full IP range configured for a subnet (e.g., 10.10.10.1 – 10.10.10.254 for VLAN 10).
  • Pool: The dynamically assignable subset of the scope after exclusions are removed.
  • Exclusions: Addresses within the scope range that DHCP will never hand out -- reserved for statically configured devices (routers, servers, printers).
  • Reservation: Binds a specific MAC address to a specific IP. The device always gets the same IP via DHCP without manual static configuration on the endpoint.
; Example scope layout for 10.10.10.0/24
Scope:       10.10.10.1  –  10.10.10.254
Exclusions:  10.10.10.1  –  10.10.10.20   (routers, switches, servers)
Dynamic Pool: 10.10.10.21 – 10.10.10.200
Reservation:  10.10.10.50  ↔  MAC AA:BB:CC:DD:EE:FF (network printer)

DHCP Options delivered with every lease:

  • Option 3: Default Gateway
  • Option 6: DNS Server(s)
  • Option 15: Domain Name
  • Option 51: Lease Duration

DHCP Relay Agents

▶

DHCP Discover messages are Layer 2 broadcasts -- they cannot cross router boundaries. In a multi-VLAN enterprise with one central DHCP server, a DHCP Relay Agent (IP Helper) solves this problem.

  • How It Works: The router's L3 interface on each VLAN intercepts the broadcast Discover, re-encapsulates it as a unicast packet, and forwards it to the central DHCP server's IP address.
  • Configuration: ip helper-address 10.0.0.5 applied to each VLAN SVI on the router/L3 switch.
  • Subnet Identification: The relay agent inserts the client's subnet into the DHCP packet (giaddr field) so the server knows which scope to assign from.
! Cisco IOS — DHCP Relay on VLAN 10 SVI
interface vlan 10
 ip address 10.10.10.1 255.255.255.0
 ip helper-address 10.0.0.5

Without a relay agent you would need a separate DHCP server on every VLAN -- relay agents allow a single highly available DHCP server pair to serve the entire enterprise.

NTP & Stratum Hierarchy

▶

NTP (Network Time Protocol) synchronizes system clocks across all network devices. Accurate time is non-negotiable for Kerberos (5-minute skew tolerance), TLS certificate validation, and SIEM log correlation.

Stratum LevelSourceNotes
Stratum 0Atomic clocks, GPS receivers, radio clocksNot on the network -- connected directly to a Stratum 1 server.
Stratum 1NTP servers connected to Stratum 0Primary time servers (NIST, pool.ntp.org). Microsecond accuracy.
Stratum 2Servers synced from Stratum 1Enterprise internal NTP servers. Millisecond accuracy.
Stratum 3–15Downstream clients syncing from higher strataWorkstations, switches, routers. Each hop adds minor drift.

Kerberos & Time: Active Directory Kerberos authentication rejects tickets if the client clock differs from the domain controller by more than 5 minutes. NTP failure = authentication failure across the entire domain.

IPAM, LDAP & Active Directory

▶

IPAM (IP Address Management)

Centralized platform that tracks all IP address allocations, DHCP scopes, and DNS records across the enterprise. Prevents IP conflicts and provides audit trails for every assignment.

LDAP (Lightweight Directory Access Protocol)

Application-layer protocol (TCP 389 / 636 for LDAPS) for querying and modifying directory services. The standard protocol used to query Active Directory user and group objects.

Active Directory (AD)

Microsoft's enterprise directory service. Stores user accounts, computer objects, groups, and GPOs. Uses Kerberos for authentication and LDAP for directory queries.

AD-Integrated DNS

DNS zones stored directly in Active Directory. Zone data replicates automatically via AD replication -- no manual zone transfers needed. All domain controllers are authoritative for the internal DNS zone.

  • DDI: DNS + DHCP + IPAM managed as a unified platform. Enterprise DDI solutions (Infoblox, BlueCat) provide a single pane of glass for all three services with audit logging and automated conflict detection.

Core Services Hardening: DNSSEC, DHCP Snooping & DAI

▶

DNSSEC

Signs DNS zone records with public-key cryptography. Resolvers verify signatures to confirm records are authentic and unmodified. Defeats cache poisoning and man-in-the-middle DNS attacks.

DHCP Snooping

Switch-level control that only permits DHCP server responses on designated trusted ports. Blocks rogue DHCP servers on untrusted access ports from handing out fake gateway addresses.

DAI — Dynamic ARP Inspection

Validates ARP packets against the DHCP snooping binding table. Drops ARP replies that don't match the legitimate IP-to-MAC binding, defeating ARP poisoning and MitM attacks.

DNS RPZ (Response Policy Zones)

Allows the recursive resolver to override DNS responses for known malicious domains, redirecting users to a block page instead of the attacker's server. Enterprise-grade DNS content filtering.

Defense Chain: DHCP Snooping builds the trusted IP-MAC binding table → DAI uses that table to validate ARP → DNSSEC ensures DNS responses aren't forged → DoT/DoH encrypts queries in transit. These four controls together eliminate the most common L2/L3 spoofing attack chains.
