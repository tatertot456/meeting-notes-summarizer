The Four Addressing Layers

▶

Network addressing is a structured, layered system where each layer answers a different question about delivery:

LayerAddress TypeExampleQuestion Answered
L2 — Data LinkMAC Address00:1A:2B:3C:4D:5EWhich specific NIC on this local link gets this frame?
L3 — NetworkIP Address192.168.10.25Which host on which network receives this packet?
L4 — TransportPort NumberTCP 443Which application process on that host receives this segment?
ApplicationDNS Namewww.example.comWhat human-readable label represents the target host?

All four address types operate in concert simultaneously for every network connection. When you load a website: DNS resolves the name to an IP, the IP routes the packet to the right host, the port delivers it to the right application, and MAC addresses handle every local hop along the way.

MAC Addresses — Layer 2 Identification

▶

A MAC (Media Access Control) address is a 48-bit identifier assigned to a network interface card (NIC). It uniquely identifies a device on a local network segment.

MAC Address Structure:
|--- 24 bits OUI ---|--- 24 bits Device ID ---|
  00  :  1A  :  2B  :  3C  :  4D  :  5E

OUI = Organizationally Unique Identifier
      Assigned by IEEE to manufacturers (e.g., 00:1A:2B = specific vendor)
Device ID = Unique serial assigned by manufacturer per NIC

Representation formats (all equivalent):

  • Linux/Unix (colon-separated): 00:1A:2B:3C:4D:5E
  • Windows (hyphen-separated): 00-1A-2B-3C-4D-5E
  • Cisco IOS (dotted pairs): 001a.2b3c.4d5e

MAC addresses are NOT permanent physical identities. Modern operating systems frequently use MAC randomization (privacy feature on smartphones/laptops), locally administered addresses, virtual machine addresses, and spoofed values. The OUI lookup only tells you the original manufacturer — it cannot identify a specific device on your network today.

Switch MAC Tables — Dynamic Learning

▶

Switches dynamically build a MAC address table (CAM table) by examining incoming frame source addresses:

  • Source inspection: When a frame arrives, the switch reads the source MAC and records MAC → Port with an aging timer
  • Destination lookup: When forwarding, switch checks destination MAC against the table — if found, sends ONLY out that port
  • Unicast flood (unknown destination): If the destination MAC is not in the table, the switch floods the frame out ALL other ports — once the target replies, its MAC is learned
Example MAC Table:
┌─────────────────────┬──────────┬──────────────┐
│ MAC Address         │ Port     │ Age (seconds)│
├─────────────────────┼──────────┼──────────────┤
│ AA:AA:AA:AA:AA:01   │ Gi0/1    │ 45           │
│ BB:BB:BB:BB:BB:02   │ Gi0/2    │ 120          │
│ CC:CC:CC:CC:CC:03   │ Gi0/3    │ 10           │
└─────────────────────┴──────────┴──────────────┘

PC1 sends frame to CC:CC:CC:CC:CC:03
→ Switch looks up CC:CC:CC:CC:CC:03 → Gi0/3
→ Frame sent ONLY out Gi0/3 — PC2 never sees it

This is why switches replaced hubs. A hub floods every frame to every port — any device can sniff all traffic. A switch isolates each port into its own collision domain, sending frames only to the intended recipient. Security and performance both improve dramatically.

IPv4, Subnetting & CIDR

▶

IPv4 is a 32-bit logical address divided into four 8-bit octets in dotted-decimal notation. The subnet mask splits the 32 bits into a network portion and a host portion.

192.168.10.25 / 24

Binary: 11000000.10101000.00001010.00011001
Mask:   11111111.11111111.11111111.00000000
        |-------- Network (24 bits) --------|-- Host (8 bits) --|

Network address: 192.168.10.0
Host range:      192.168.10.1 – 192.168.10.254
Broadcast:       192.168.10.255
Usable hosts:    254

CIDR /26 conversion example:

26 binary 1s: 11111111.11111111.11111111.11000000
Final octet:  128 + 64 = 192
Subnet mask:  255.255.255.192

/26 network: 64 addresses total, 62 usable hosts

Historical IP classes (now replaced by CIDR):

ClassFirst OctetDefault MaskMax HostsUse
A1–126/8 (255.0.0.0)16.7 millionLarge organizations
B128–191/16 (255.255.0.0)65,534Medium organizations
C192–223/24 (255.255.255.0)254Small networks
D224–239N/AN/AMulticast
E240–255N/AN/AExperimental/reserved

CIDR replaced classful addressing because classful wasted massive IP blocks. A company needing 300 hosts had to take a Class B (/16 = 65,534 hosts) — wasting 65,234 addresses. CIDR allows /23 (510 hosts) — a near-perfect fit. Modern routers bypass class boundaries entirely and use variable prefix lengths (/20, /23, /27, etc.).

Private IPv4 Ranges & NAT

▶

Three private IPv4 ranges are reserved for internal networks and are non-routable on the public internet:

RangeCIDRAddressesTypical Use
10.0.0.0 – 10.255.255.255/816.7 millionLarge enterprises, data centers
172.16.0.0 – 172.31.255.255/121 millionMedium networks
192.168.0.0 – 192.168.255.255/1665,536Home networks, small offices

How NAT bridges private to public:

  • ISPs drop packets with private source IPs — private addresses cannot reach the internet directly
  • An edge router or firewall with NAT translates the private source IP to the router's public IP when packets leave
  • The NAT router tracks source ports to route incoming replies back to the correct internal host
Internal: 192.168.1.25:51234  →  NAT Router  →  Public: 203.0.113.1:51234
                                    ↑
                          Tracks this mapping in state table
                          Reply arrives at public IP → forwarded to 192.168.1.25

The same private IP range (192.168.1.x) can exist in millions of separate organizations worldwide without conflicts — because private addresses never appear on the public internet. This is how IPv4 lasted decades longer than its designers expected. IPv6 eliminates the need for NAT by giving every device a globally unique address.

IPv6 — 128-Bit Addressing

▶

IPv6 is a 128-bit address represented as eight groups of 16-bit hexadecimal values separated by colons. 2^128 addresses — effectively unlimited.

Full address:  2001:0db8:1234:5678:abcd:ef01:2345:6789

Standard /64 split:
┌────────────────────────────────┬─────────────────────────────────┐
│    Network Prefix (64 bits)    │     Interface ID (64 bits)      │
│  2001 : 0db8 : 1234 : 5678    │  abcd : ef01 : 2345 : 6789      │
│  [48 bits public] [16 subnet]  │  [NIC identifier]               │
└────────────────────────────────┴─────────────────────────────────┘

Compression rules:

  • Leading zero suppression: 0db8 → db8, 0042 → 42, 0000 → 0
  • Double colon (::): replaces ONE continuous sequence of all-zero groups
  • Single-use rule: :: can only appear ONCE — multiple :: would be mathematically ambiguous to expand
Compression example:
Raw:        2001:0db8:0000:0000:0008:0000:0000:4122
Step 1:     2001:db8:0:0:8:0:0:4122  (leading zeros removed)
Step 2:     2001:db8::8:0:0:4122     (longest zero run compressed)
Note: Two separate zero sequences — only the longest gets ::

Expansion example:
Compressed: fe80::1
Groups:     fe80 and 1 = 2 groups; need 8 total
Expanded:   fe80:0000:0000:0000:0000:0000:0000:0001

IPv6 eliminates broadcast entirely — replaced by multicast. It also includes SLAAC (Stateless Address Autoconfiguration) allowing devices to configure their own addresses without DHCP, and NDP (Neighbor Discovery Protocol) replacing ARP. Global IPv6 adoption sits around 48.8% of Google traffic as of recent data, with India, France, and the US leading adoption above 50–60%.

IPv6 advantages over IPv4: simplified 40-byte fixed header (faster hardware routing), no NAT required, native neighbor discovery, hierarchical /48 prefix allocation giving organizations 65,536 /64 subnets.

Traffic Delivery Types

▶
TypePatternDescriptionExample
UnicastOne-to-OneSingle source to single destinationStandard web browsing, SSH, file transfer
MulticastOne-to-GroupDelivers only to hosts that have joined the multicast groupVideo streaming, routing protocol updates (OSPF), IPTV
BroadcastOne-to-All (LAN)Sends to all devices in a Layer 2 broadcast domain — IPv4 onlyARP requests, DHCP discovery
AnycastOne-to-NearestSame IP assigned to multiple servers; routing sends to the topologically closestDNS root servers, CDNs, IPv6 default gateways

IPv6 eliminates broadcast entirely — it was replaced by multicast. This is a significant efficiency improvement. IPv4 broadcast frames are sent to every device on the LAN segment regardless of interest; multicast only delivers to subscribed recipients. Anycast is used by every major CDN and DNS provider — the same IP address (like 8.8.8.8) can be served from hundreds of global locations, with routing automatically selecting the nearest one.

Ports, Sockets & Well-Known Services

▶

A port number is a 16-bit identifier (0–65,535) that associates a packet payload with a specific application or service on a host. IP addresses identify the HOST; ports identify the SERVICE on that host.

RangeNamePurpose
0–1023Well-Known PortsReserved by IANA for standard services (HTTP, HTTPS, SSH, DNS, SMTP)
1024–49151Registered PortsAssigned to specific application products and vendor services
49152–65535Dynamic / EphemeralAssigned temporarily by OS as source ports for outbound client connections

Common well-known ports:

TCP 22   — SSH (Secure Shell)
TCP 23   — Telnet (insecure, legacy)
TCP 25   — SMTP (email sending)
TCP 80   — HTTP
TCP 443  — HTTPS
UDP 53   — DNS queries
UDP 67/68 — DHCP
TCP 3389 — RDP (Remote Desktop)

The socket pair: combining IP + port creates a unique communication endpoint:

Client:  192.168.1.50:53122  (ephemeral source port)
Server:  93.184.216.34:443   (destination HTTPS)

Socket pair uniquely identifies this specific session.
Multiple browser tabs = multiple ephemeral ports = multiple simultaneous sessions.

Port Security & Attack Surface

▶

Every open port and listening service is a potential attack vector. Minimizing open ports directly reduces the attack surface.

Port States

Open: active service listening — reachable and responding. Closed: host reachable but no daemon listening. Filtered: firewall or security gateway is dropping probe packets — state unknown to scanner.

Principle of Least Privilege

A secure web server needs ONLY TCP 443. Running FTP (21), Telnet (23), or RDP (3389) unnecessarily expands the attack vector. Every unnecessary open port is a vulnerability waiting to be exploited.

Firewall ACL Policy

Explicit deny-all with selective allow: "ALLOW TCP 443; DENY ALL OTHER INBOUND." Drop unrequested inbound connections. Never rely on security through obscurity.

Hardening Practices

Regular port audits (nmap), host-level firewalls, disabling inactive services/daemons, monitoring for unexpected open ports, and patching listening services promptly.

The encapsulation chain ties all four address layers together: Application data → TCP header (ports) → IP header (addresses) → Ethernet frame (MACs) → physical bits. Every layer's address operates independently but in concert. A failure at any layer breaks delivery — understanding which layer failed is the key to troubleshooting.
