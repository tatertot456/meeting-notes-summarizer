Layer 3 & 4 Header Identification

▶

Two distinct numbering systems direct payloads to the correct protocol and application — one at Layer 3, one at Layer 4.

IP Protocol Numbers (L3)

A 1-byte field in the IPv4 header (called "Next Header" in IPv6) that tells the router which Layer 4 engine to hand the payload to. The IP header is a protocol router, not just an address carrier.

Port Numbers (L4)

16-bit identifiers that associate incoming data with a specific running application. Pairing an IP address with a port creates a socket — a unique network endpoint (e.g., 10.0.0.5:443).

Protocol NumberProtocolPurpose
1ICMPDiagnostics (ping, traceroute, error reporting)
2IGMPMulticast group membership
6TCPReliable connection-oriented transport
17UDPLightweight connectionless transport
50ESPIPsec encrypted payload

The identification chain: IP Protocol 6 tells the router "hand this to TCP." TCP port 443 tells the OS "hand this to the HTTPS web server process." Two numbering systems, two different layers, working together to route every packet to the right application.

TCP Mechanics — Handshake, Sequencing, and Flow Control

▶

Three-way handshake establishes the connection before any data flows:

Client → Server:  SYN         (I want to connect)
Server → Client:  SYN-ACK     (OK, I acknowledge your SYN)
Client → Server:  ACK         (Connection established)

Sequence and acknowledgment numbers give TCP its reliability guarantee. Every byte is numbered. Receivers use the sequence numbers to reassemble out-of-order segments, discard duplicates, and request retransmission of anything lost.

Flow Control (Sliding Window)

The receiver advertises its available buffer space in the Window Size field. The sender throttles its output to never overflow the receiver's memory. Protects the destination host.

Congestion Control

Protects the network itself from overload. Managed by a private variable on the sender side that tracks network congestion signals and reduces transmission rate when the network shows stress.

Flow control and congestion control solve different problems. Flow control: "don't overwhelm ME (the receiver)." Congestion control: "don't overwhelm the NETWORK between us." Both are managed by TCP without any application awareness.

Open Standards vs. Proprietary Protocols

▶

Open Standards

Developed by bodies like IETF, IEEE, or W3C. Freely implementable by any vendor. Examples: IP, TCP, UDP, HTTP, DNS, 802.3 Ethernet, LLDP. Enable multi-vendor interoperability and reduce lock-in risk.

Proprietary Protocols

Owned by a single organization. Implementation restricted or licensed. Examples: Cisco CDP, legacy IGRP, AppleTalk. Often deliver advanced features faster than standards bodies can ratify, but lock you into one vendor ecosystem.

The practical tension: proprietary protocols often innovate faster and offer tighter integration, but they create dependency. A network built entirely on Cisco CDP cannot be monitored by an HP or Linux device. The modern enterprise trend is toward open standards (LLDP over CDP, OSPF over EIGRP) to preserve flexibility.

Directory Services

▶

A directory service organizes, manages, and locates network resources — users, computers, printers, servers, and email addresses. It provides a security structure so users can access resources without knowing their physical location.

ServiceDescription
NDS (Netware Directory Services)The first enterprise directory service. Now obsolete — displaced by Active Directory.
Active Directory (AD)Microsoft's directory service. Widely adopted enterprise standard since Windows 2000 Server. Drove NDS out of corporate environments.
LDAPLightweight Directory Access Protocol. An open standard for accessing and maintaining distributed directory information over IP. AD uses LDAP as a core protocol at every version.

Active Directory achieves multi-vendor compatibility through open components: LDAP for directory access, Kerberos for authentication, and DNS for service discovery. The underlying protocols are open standards even though AD itself is Microsoft's product. LDAP is also used independently as a central store for usernames and passwords across Linux and mixed environments.

Routing Boundaries — IGP vs. EGP

▶

An Autonomous System (AS) is a collection of networks, routers, and IP subnets under one administrative entity — a university, corporation, or ISP. Routing protocols split along this boundary.

Interior Gateway Protocols (IGP)

Exchange routing information WITHIN an AS. Goal: find the mathematically fastest path. Examples: RIP, OSPF, EIGRP. Used inside your organization's own infrastructure.

Exterior Gateway Protocols (EGP)

Exchange routing information BETWEEN separate Autonomous Systems. Goal: enforce policy and negotiate transit paths. Only example in production: BGP (Border Gateway Protocol).

The 15-hop limit is RIP's fatal flaw for large networks. It was designed when networks were small. A value of 16 means "unreachable" — so any path requiring more than 15 routers simply doesn't exist in RIP's view of the world. OSPF and EIGRP replaced RIP for any network of meaningful scale.

OSPF & EIGRP

▶

OSPF (Open Shortest Path First)

Open standard (IETF). Link-state protocol — each router builds a complete map of the network topology. Uses Dijkstra's algorithm to calculate the shortest path. Scales to large enterprise networks. No hop limit. Converges fast after topology changes.

EIGRP (Enhanced Interior Gateway Routing Protocol)

Originally Cisco proprietary, later opened. Advanced Distance Vector using the DUAL algorithm. Considers bandwidth, delay, reliability, and load — not just hop count. Very fast convergence. Still common in Cisco-heavy environments.

FeatureOSPFEIGRP

BGP — The Internet's Routing Protocol

▶

Border Gateway Protocol (BGP) is the only EGP in production use. It routes traffic between the ~80,000 Autonomous Systems that make up the public internet. BGP does not optimize for speed — it enforces policy.

AS_PATH Routing

BGP routes by policy, not raw speed. Each AS advertisement includes the list of AS numbers the route has passed through. Routers choose paths based on these policies — a shorter AS_PATH is preferred by default.

iBGP vs. eBGP

eBGP runs between routers in different Autonomous Systems (external). iBGP runs between routers inside the same AS to distribute external routes internally. Both use the same protocol, different relationship types.

Major internet backbone operators (Tier 1 ASes):

  • AT&T (AS7018), Verizon/Cogent (AS701/AS174), Lumen/CenturyLink (AS209)
  • Deutsche Telekom (AS3320), NTT Communications (AS2914)
  • Telecom Italia Sparkle/Seabone (AS6762)

Major physical interconnection hubs: Equinix (Ashburn VA, Chicago, Singapore, Frankfurt), One Wilshire (LA — US-Asia gateway), 60 Hudson Street (New York — transatlantic hub).

BGP is simultaneously the most critical and most fragile protocol on the internet. A misconfigured BGP announcement can accidentally route millions of users' traffic through the wrong country — this has happened multiple times in production. BGP hijacking (advertising someone else's IP block) is a real attack that requires out-of-band coordination to fix.

SNMP, CDP & LLDP — Network Management

▶

SNMP (Simple Network Management Protocol) has three components:

SNMP Manager

The central monitoring dashboard. Periodically polls agents using GET requests for CPU, interface stats, and packet drop rates.

SNMP Agent

Software running on network devices. Responds to polls and sends unsolicited Trap/Inform alerts immediately when events occur (interface down, temperature spike).

MIB (Management Information Base)

A hierarchical database defining exactly which data points a device can report on or configure — the schema for everything SNMP can see.

SNMPv3

SNMPv1/v2c used plaintext community strings (essentially passwords sent in the clear). SNMPv3 adds authentication, packet integrity, and payload encryption.

ARP & ICMP

▶

The addressing gap: a host knows the target IP address but needs the MAC address to build an Ethernet frame. ARP bridges this gap for IPv4.

ARP (IPv4)

Broadcasts "Who has 192.168.10.5?" to the entire LAN. The target replies with its MAC. Results cached in the ARP table. Vulnerability: no authentication — ARP Spoofing lets an attacker claim to be the gateway and intercept all traffic (Man-in-the-Middle).

IPv6 Neighbor Discovery (ND)

Replaces ARP entirely. Uses ICMPv6 multicast solicitation and advertisement — no LAN-wide broadcast. Eliminates the ARP spoofing attack surface by design.

ICMP — diagnostics and error reporting:

  • Error messages: Destination Unreachable, Time Exceeded (TTL expired), Port Unreachable
  • Ping: sends ICMP Echo Request, receives Echo Reply — verifies L1–L3 reachability and measures round-trip time
  • Traceroute: sends packets with TTL=1, then TTL=2, etc. Each hop drops TTL to zero and returns a Time Exceeded message, revealing the full path to the destination

SFTP is not "FTP with SSH bolted on" — it is a completely separate protocol that happens to run over SSH. The name is misleading. It has no relationship to FTP's architecture. Its single-port design makes it the correct choice for any modern file transfer requirement.

TLS, SSH, IPsec & Cryptography

▶

Cryptographic systems comparison:

Symmetric Cryptography

Same key encrypts and decrypts. Very fast for bulk data. Problem: how do two parties safely share the secret key before communication begins? (Key Distribution Problem). Example: AES.

Asymmetric Cryptography

Public key (shared openly) encrypts; private key (kept secret) decrypts. Solves key distribution but is computationally slow. Examples: RSA, Diffie-Hellman, ECC.

Hybrid Approach (TLS/SSH)

Use asymmetric cryptography to safely exchange a shared secret, then switch to symmetric encryption for bulk data transfer. Gets the security of asymmetric with the speed of symmetric.

Application security protocols:

ProtocolPortPurpose
TLS (replaces SSL)VariesEncrypts application sessions using digital certificates from a CA

IPsec — network layer VPN security:

AH (Authentication Header)

Guarantees packet integrity and source authentication. Does NOT encrypt the payload — anyone can still read the data, but they cannot modify it without detection.

ESP (Encapsulating Security Payload)

Provides full payload encryption plus integrity and authentication. The standard choice for real VPN security.

Transport Mode

Encrypts the payload only. Original IP header stays intact. Used for host-to-host direct connections.

Tunnel Mode

Wraps the entire original IP packet in a new IP header. Hides internal subnet structure. Industry standard for site-to-site corporate VPNs.

SSL is dead. Every reference to "SSL" in modern infrastructure actually means TLS. TLS 1.3 is the current standard — TLS 1.0 and 1.1 are deprecated and disabled by default in modern browsers and servers. If you configure a server to accept SSLv3, you have introduced a known exploitable vulnerability.
