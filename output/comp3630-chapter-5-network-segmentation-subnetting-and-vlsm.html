Why Segment a Network?

▶

Segmentation divides one network into logical or physical subnetworks (subnets). A flat network where every device shares the same broadcast domain creates serious problems at scale.

Flat Network Problems

Every ARP and DHCP broadcast floods all devices. One compromised device can scan and attack everything. No logical boundaries mean no access control enforcement.

Performance

Restricts broadcasts strictly to their VLAN — other segments never see the noise.

Security & Containment

A compromised student laptop stays on the student VLAN and cannot reach corporate servers.

Granular Access Control

ACLs and firewall rules define exactly which groups can reach specific systems and ports.

Scalability

Organize address blocks hierarchically by department, function, building, or location.

Targeted Troubleshooting

Isolates faults, broadcast storms, and duplicate IPs to a single subnet zone.

Physical vs. Logical Segmentation

▶

Physical Segmentation

Separate switches, firewalls, copper runs, and patch panels per segment. Air-gapped isolation — traffic physically cannot cross without a router. Extremely secure but expensive and inflexible. Adding one user may require new cabling.

Logical Segmentation (VLANs)

Same physical switch and cables, but packets are tagged and isolated in logical lanes. Administrators reassign ports to different VLANs in seconds from a terminal. Security depends on ACL and firewall configuration at Layer 3.

VLANs deliver the isolation of physical segmentation without the cost. The tradeoff: security is now software-defined rather than physically enforced. A misconfigured ACL or trunk port can collapse the boundary entirely. Physical segmentation is still used for the most sensitive environments (payment systems, classified networks).

Binary Math — The Foundation of All Subnetting

▶

IPv4 addresses are 32-bit binary strings divided into four 8-bit octets. Every subnetting calculation happens in binary — decimal is just the human-readable representation.

The 8-bit positional weight matrix — memorize this row:

Bit position: 7    6    5    4    3    2    1    0
Weight:      128   64   32   16    8    4    2    1
Max value:   128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255

Binary to decimal: identify which bit positions are 1, sum their weights.

Convert 10110110 to decimal:
Bits:    1    0    1    1    0    1    1    0
Weights: 128  64   32   16   8    4    2    1
Active:  128  —    32   16   —    4    2    —

128 + 32 + 16 + 4 + 2 = 182

Decimal to binary: systematic subtraction — test each weight from 128 down to 1. If the weight fits in the remainder, write 1 and subtract; otherwise write 0.

Convert 182 to binary:
182 ≥ 128? YES → write 1, remainder = 54
54  ≥ 64?  NO  → write 0
54  ≥ 32?  YES → write 1, remainder = 22
22  ≥ 16?  YES → write 1, remainder = 6
6   ≥ 8?   NO  → write 0
6   ≥ 4?   YES → write 1, remainder = 2
2   ≥ 2?   YES → write 1, remainder = 0
0   ≥ 1?   NO  → write 0

Result: 10110110 ✓

Fluency in the 8-bit weight row (128, 64, 32, 16, 8, 4, 2, 1) is the single most important prerequisite for subnetting. Everything else — CIDR conversion, block size calculation, bitwise AND — is just applying these weights in different ways.

Subnet Masks & Bitwise AND

▶

A subnet mask filters a 32-bit IP address into its network and host portions. The 1 bits lock the network prefix; the 0 bits designate the host space.

Standard /24 mask in binary:
11111111.11111111.11111111.00000000  =  255.255.255.0
|-------- 24 ones (network) ---------|--- 8 zeros (host) ---|

Bitwise AND determines which network a host belongs to:

IP:   192.168.10.25  =  11000000.10101000.00001010.00011001
AND
Mask: 255.255.255.0  =  11111111.11111111.11111111.00000000
                        ─────────────────────────────────────
Net:  192.168.10.0   =  11000000.10101000.00001010.00000000

AND rule: 1 AND 1 = 1,  1 AND 0 = 0,  0 AND 0 = 0

/26 worked example — 192.168.10.75:

IP last octet  75:  01001011
Mask last octet 192: 11000000
AND:                 01000000  =  64

Network ID: 192.168.10.64/26

If two devices share the same AND result they are on the same local subnet and communicate directly. If their network IDs differ, the packet goes to the default gateway (router) for forwarding. This AND operation runs inside every router and Layer 3 switch on every packet.

Bit Borrowing — Creating Subnets

▶

Subnetting means moving the network/host boundary to the right — "borrowing" bits from the host portion and making them network bits. Two exponential formulas govern the math:

Subnets created  = 2^n   (n = bits borrowed from host portion)
Usable hosts     = 2^h - 2  (h = host bits remaining)
                             (-2 for network ID and broadcast address)

Borrowing from a /24 block — the design curve:

PrefixBits BorrowedSubnetsHosts per SubnetMask
/2401254255.255.255.0

/273830255.255.255.224

/306642255.255.255.252

Every bit borrowed doubles the subnet count and cuts the hosts per subnet in half. /30 (2 usable hosts) is the standard for point-to-point router links — one address per router interface, nothing wasted.

Block Size Shortcut — Fast Subnet Boundaries

▶

Binary AND every time is slow in production. The block size shortcut finds subnet boundaries in seconds:

Step 1: Block size = 256 - last octet of subnet mask
   /26 mask = 255.255.255.192
   Block size = 256 - 192 = 64

Step 2: Subnet IDs are multiples of block size starting at .0
   Subnet 1: 192.168.10.0
   Subnet 2: 192.168.10.64
   Subnet 3: 192.168.10.128
   Subnet 4: 192.168.10.192

Step 3: For each subnet block:
   Network ID:       first address (e.g., 192.168.10.64)
   First usable:     Network ID + 1  (e.g., 192.168.10.65)
   Broadcast:        Next network ID - 1  (e.g., 192.168.10.127)
   Last usable:      Broadcast - 1  (e.g., 192.168.10.126)

To find which subnet an IP belongs to: divide the host octet by the block size and round down to the nearest multiple. IP 192.168.10.75 on /26 → 75 ÷ 64 = 1 remainder → nearest multiple = 64 → subnet is 192.168.10.64/26. No binary needed.

CIDR — Classless Inter-Domain Routing

▶

Classful addressing (Class A /8, Class B /16, Class C /24) wasted massive blocks. A company needing 1,000 hosts had to take a Class B (65,534 hosts) — wasting 64,500+ addresses. CIDR replaced fixed class boundaries with flexible prefix lengths.

Flexible Boundaries

Any prefix length at any bit position: /22, /26, /27, /28. Size the subnet to fit the actual device population.

Slash Notation

192.168.10.0/26 means 26 consecutive 1-bits in the mask. Replaces writing out 255.255.255.192 every time.

Route Aggregation

Four contiguous /24 networks (10.20.0.0 through 10.20.3.0) can be summarized as one 10.20.0.0/22 route — drastically reducing routing table size and CPU load.

Route aggregation (summarization) is CIDR's biggest operational benefit. Instead of advertising hundreds of specific routes, a router advertises one summary. Smaller routing tables mean faster lookups and less memory. Modern internet routing is completely dependent on this.

VLSM — Variable Length Subnet Masking

▶

Without VLSM, every subnet in a block must be the same size — a 2-host router link wastes the same space as a 60-host department subnet. VLSM allows different prefix lengths within the same address block.

The Golden Rule of VLSM: always allocate largest subnets first, work down to smallest. Allocating out of order causes subnet ranges to overlap, breaking routing protocols and disabling connectivity.

VLSM design order:

  • Sort requirements largest to smallest
  • Find the smallest prefix that fits (2^h - 2 ≥ hosts needed)
  • Allocate that block starting at the next available address
  • Record the exact range used, then move to the next requirement

Case study — subnetting 192.168.0.0/24 for four departments:

Engineering (largest)100/25 (126 hosts)192.168.0.0/25.1 – .126
Sales50/26 (62 hosts)192.168.0.128/26.129 – .190
HR20/27 (30 hosts)192.168.0.192/27.193 – .222

Remaining space (192.168.0.228 – 192.168.0.255) is preserved for future growth — a key advantage of VLSM over equal-size subnetting.
